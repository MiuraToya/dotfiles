# Claude Code サンドボックス

`--dangerously-skip-permissions`(バイパスモード)をホストで直接使うのは危険なので、
**コンテナの中に閉じ込めて** 動かすための一式です。
万一危険なコマンドが実行されても、被害をコンテナ内に限定するのが目的。

特定のプロジェクトに依存しません。**任意のリポのルートで起動すると、そのリポが
`/workspace` にマウントされて** すぐ使えます。

## 置き場所と使い方

このフォルダ(`claude-sandbox/`)は好きな場所に置けます(例: `~/tools/claude-sandbox`)。
使いたいリポのルートで `run.sh` を実行するだけ:

```bash
# 任意のリポのルートで
~/tools/claude-sandbox/run.sh              # そのリポをマウントしてバイパスモード起動
~/tools/claude-sandbox/run.sh bash         # 中を調べたいときはシェルで入る
ENABLE_FIREWALL=1 ~/tools/claude-sandbox/run.sh   # 通信も許可リストに制限
```

よく使うならエイリアスにすると "さくっと" 使えます:

```bash
alias claude-box='~/tools/claude-sandbox/run.sh'
# → どのリポでも `claude-box` と打つだけ
```

認証は次のどちらか:
- ホストに `ANTHROPIC_API_KEY` があれば自動で渡されます。
- 無ければ初回に `claude` のログインを実行。認証情報は **ホストではなく**
  named volume(`claude-config`)に保存され、**どのリポから起動しても使い回せます**。

## 多層防御の考え方

| 層 | 仕組み | 防ぐもの |
|----|--------|---------|
| 1. 非 root 実行 | `node`(uid 1000)で起動 | コンテナ内の特権操作 |
| 2. FS 隔離 | 書込可能はマウントしたリポ(`/workspace`)のみ | ホストのファイル破壊 |
| 3. リソース上限 | mem / cpus / pids 制限 | fork bomb・暴走 |
| 4. egress 制限(任意) | iptables 許可リスト | 情報持ち出し・C2 通信 |

> コンテナは VM ほど強い隔離ではない(カーネル共有)。「ホストで bypass を直叩きするより桁違いに安全」だが万能ではない、という前提で使ってください。

## ホストと共有する / しないの判断

「共有した方が便利では？」というものを、隔離の目的と天秤にかけて決めています。

### ✅ 共有する(マウントする)

- **起動したリポ** → `/workspace` に read-write。これが「意図した影響範囲」。
  ここだけは壊されても git で戻せる範囲に収める。
- **`~/.gitconfig`** → read-only。コミット作者を正しくするためだけ。書込不可にして改ざんを防ぐ。

### ❌ 共有しない(コンテナ内に閉じる)

- **ホストの `~/.claude`** → named volume に隔離。ホストの設定/トークンを汚染・流出させない。
- **`~/.ssh`、`~/.aws`、`~/.config/gcloud`、各種トークン** → 一切渡さない。
  これらを渡すと「危険コマンドで鍵を抜かれてクラウド資源を破壊」が成立してしまい、隔離の意味が消える。
- **`/var/run/docker.sock`** → 絶対にマウントしない。Docker ソケットを渡すと
  そこから実質ホスト root を取れる(コンテナ脱出)ので、サンドボックスとして本末転倒。
- **ホームディレクトリ全体・シェル履歴** → 渡さない。

### ⚠️ 判断が要るもの

- **git push したい** → ホスト鍵を渡すのは避け、**スコープを絞った PAT** を
  `GIT_*` env や `gh auth` でコンテナ内に与えるのが安全。使い終えたら失効できる。
- **ネイティブ依存を含む依存ディレクトリ**(`node_modules`、`.venv` など) → ホスト(例: macOS)で
  入れたバイナリは Linux コンテナと ABI が違い壊れることがある。コンテナ内で入れ直すのが安全。
- **ネットワーク** → 既定はフルアクセス(API 到達に必要)。持ち出しが心配なら
  `ENABLE_FIREWALL=1` で Anthropic / GitHub / npm のみ許可に絞る。

## 他言語リポで使う

ベースは Node 入りだが、Claude 本体は Node 非依存。Python や Go など別のツールが要る場合は
`Dockerfile` の「拡張ポイント」コメント部分に `apt-get install ...` を足して再ビルドする。

## さらに固める(任意)

- ファイアウォールを使わないなら `docker-compose.yml` の `cap_add` を削除し、
  `security_opt: ["no-new-privileges:true"]` を足すとより堅い。
- 完全オフラインにしたいタスクなら `network_mode: none`(ただし API も使えなくなる)。

## 更新

Claude Code は公式ネイティブインストーラ(`claude.ai/install.sh`)でイメージに焼き込んでいる。
更新は再ビルドで:

```bash
docker compose build --no-cache
```

> 初回ビルドはネイティブバイナリのダウンロードで3〜4分ほどかかります(以降はキャッシュ)。
